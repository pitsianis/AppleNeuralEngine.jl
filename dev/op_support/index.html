Op support

Generated by tools/probe_ops.jl on Apple M2 Max, macOS 27.0.1, 2026-10-29. Each op runs in a small fp16 program; err is the maximum absolute error relative to the largest reference value (fp16 rounding gives ~1e-3); ≈ marks results within 10% (a coarse hardware approximation). "compile fails (InvalidMILProgram)" means the ANE compiler's MIL validation rejected the op; every argument encoding we tried (inline or const literals, other axes, other modes) was rejected. Core ML may lower these ops to others before they reach the ANE. The ANE is a private, undocumented target, so this table can change with macOS releases. Re-run the probe on your machine.

129 of 167 probed cases compile and run.

Not probed (they need control flow, dynamic shapes or state, which this package does not support yet): cond, while_loop, make_list and the list_* ops, non_zero, non_maximum_suppression, classify, read_state, slice_update, affine, resample, crop_resize, reshape_like, and the constexpr_* compression ops other than constexpr_affine_dequantize.

Observed constraints, independent of the op:

  • Computation must be fp16: the same ops on fp32 tensors do not compile (cast inputs).
  • A trailing identity op cannot be a program output.
  • Tensor buffers need a 64-byte aligned row stride, which this package provides, so any innermost size works.
